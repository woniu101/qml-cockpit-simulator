# 沉浸式整车模拟器 · 第二版方案

## 产品边界

将模拟器做成一台可操作的虚拟车辆。模拟器负责实体输入、整车状态、互锁和可控的测试环境，车机负责触屏操作、3D 车辆、地图、媒体、语音和用户设置。单屏时可查看车机联动摘要，双屏时以真正运行的车机窗口作为第二屏。

实车参考分两部分。2017–2023 Model 3 的挡杆、驻车按钮、制动换挡和窗控适合参考交互关系，也与车机当前 3D 素材的年代相近。比亚迪秦 PLUS DM-i 的用户手册把驾驶员门板、灯光、雨刮和双闪分为实体操作区，可用来检查布局是否遗漏常用硬件。仪表、换挡与拨杆组合采用本项目自己的通用新能源车布局。 [Model 3 车主手册](https://www.tesla.com/ownersmanual/2017_2023_model3/zh_cn/) · [比亚迪秦 PLUS DM-i 用户手册](https://www.byd.com/material/domestic-official/user-manual/dynasty/2026%E6%AC%BE%E7%A7%A6PLUS%20DM-i%E7%94%A8%E6%88%B7%E6%89%8B%E5%86%8C260430-new.pdf)

## 五个工位

| 工位 | 界面重点 |
|---|---|
| 驾驶 | 上半部是视线中心，车速和实际挡位最大，READY、里程、SOC、告警居次。下方按操作区组织挡杆、P 键、左宽右窄的踏板和灯光。行驶时保留必要提示，诊断数字折叠 |
| 车身 | 俯视图用车头方向建立位置感，门把手、备厢和后视镜在对应部位。主驾门板显示四窗翘板、门锁和实际窗位，目标开度只在执行中显示。首版可用二维轮廓，车机侧继续显示 3D |
| 舒适 | 双区旋钮位于中部，AUTO、A/C、SYNC、除雾在一排。出风方向、座椅加热放次级区。初期只模拟设定值和开关 |
| 补能 | 驻车与接口状态在顶部，左侧车尾接口可操作，右侧桩屏显示功率、当前与目标 SOC、估算用时。插枪、充电、暂停、达标和拔枪各有反馈 |
| 联调 | 源连接、会话、最近快照时间、请求 ID、动作状态和故障注入。区分实体操作和直接注入。请求来源需要触控/语音细分时，再加来源字段 |

双屏模式固定显示仪表和必要操作。单屏或较窄窗口把车机联动摘要收到次级位置。浅绿用于已生效，琥珀用于等待与过期，红色用于拒绝或故障，并始终配文字。原型里的车机联动栏是本地演示状态。

## 核心行为

- **挡位和踏板。** 第一阶段使用纵向速度模型。D/R 有驱动力，N 无驱动力但可滑行和制动，P 保持静止。刹车优先，松油门后减速，D/R 换向和挂 P 要求先停稳。沉浸驾驶从 P 进入 D/R 要求踩刹车，车机现有「进入行驶演示」保留为明确的脚本场景入口。实际挡位仅在校验通过后更新。Qt 失焦、鼠标释放和输入取消都要清零踏板；需要覆盖充电枪、开门及备厢未闭合等现有互锁。
- **门窗。** 翘板按住时下发运动方向对应的目标，释放时走现有停止操作。每次按压要有明确归属，另一端换目标后，旧操作的释放只清理自己的输入，避免把另一端的新目标停掉。单触发全开/全关、后窗锁和防夹可作为后续场景。防夹先由模拟器注入障碍事件并验证反向释放。
- **补能。** P 挡开盖 → 插枪 → 开始 → 到达目标或暂停 → 拔枪 → 关盖。保持插枪时挡位互锁。降低目标值不会降低实际 SOC。暂停遥测后，车机保持最后确认值并停止能量动效，恢复后按完整快照更新。
- **灯光和视野。** 转向灯、双闪、近光、雨刮应有实际状态和可见效果。刹车灯由模拟制动输入导出，倒车灯由 R 挡导出。方向盘、转向角和倒车画面在有横向轨迹与停车场场景后再做。此前仪表道路只提供速度反馈，避免出现方向盘能转却无法改变轨迹的操作。
- **更深的实车功能。** 可以后续加入电子驻车、Auto Hold、能量回收、低电量与胎压/安全带提示等，每项都对应独立状态和可复现场景。ABS、气囊、辅助驾驶只适合做可注入的状态提示或独立演示，不作为本项目的车辆安全功能。 [Model 3 驾驶与安全功能目录](https://www.tesla.com/ownersmanual/2017_2023_model3/zh_cn/)

## 实施顺序与验收

1. **驾驶和车身闭环。** 在模拟器新增 Qt Quick 界面，通过窄接口调用既有 C++ 模型与服务。保留原调试控制台和 headless 启动。踏板先做本地输入，沿用协议的挡位、速度、里程和 SOC 字段。v1 对 P/N 的速度约束保持原义，要让 N 挡滑行在两端可见，随行驶协议扩展一起上线。首批场景为驾驶加减速、四窗长按和停止、插枪时阻止换挡。 [Qt Quick 文档](https://doc.qt.io/qt-6/qtquick-index.html)
2. **车身之外的双向控制。** 扩展协议并同步两个仓库。空调、座椅和灯光在外部模式下由模拟器给出实际状态，触屏、实体控件和语音都通过同一执行入口。内置模式与电脑映射继续使用各自状态源。状态机和互锁留在 C++，QML 只负责输入和显示。
3. **场景与故障验收。** 加入出发、途中控窗、倒车、到站充电及断线恢复场景。保留当前双进程测试，补踏板丢焦、同资源竞争、重复点击、遮挡和窄屏、坏包和重连。日志要能分辨接受、执行中、完成、取消、拒绝和超时。语音控窗可用 WAV 回放验证，真人麦克风仍单列验收。

| 首批验收脚本 | 必须观察到 |
|---|---|
| 踩刹车挂 D → 加速 → 滑行 → 刹停 → 挂 P | 两端挡位和车速一致，D 挡累计距离推动车机导航，失焦后无残留踏板输入 |
| 模拟器半途停左前窗 → 车机设右后窗 30% → 助手再开一点 | 玻璃与两端读数一致，助手在实际到位后回复。两端抢控同一扇窗时，旧操作有明确结果 |
| P 挡插枪充电 → 尝试挂 D → 快进达标 → 拔枪关盖 | 挂挡被拒且仍为 P，两端功率、目标和充电动效一致，拔枪关盖后可以继续驾驶 |
| 暂停遥测 → 恢复或重启模拟器 | 车机保留并标记过期状态，不重放未确认指令，重新拿到完整快照后恢复 |
